Häufig gestellte Fragen

Was macht URL-Codierung?

Wandelt Zeichen, die in einer URL nicht sicher sind (Leerzeichen, &, ?, #, und andere), in ein Prozentzeichen gefolgt von ihrem Hex-Code um - zum Beispiel wird ein Leerzeichen zu %20 - damit der Text sicher in eine URL eingefügt werden kann, wie eine Suchanfrage oder ein Parameterwert.

Warum wird ein Leerzeichen zu %20 statt einem Pluszeichen (+)?

Beide werden in der Praxis verwendet: %20 ist die standardmäßige Prozentcodierung für ein Leerzeichen überall in einer URL, während + speziell „Leerzeichen“ nur innerhalb von URL-Query-Strings (formularcodierte Daten) bedeutet, eine Altkonvention aus HTML-Formularen. Dieses Tool verwendet %20, die universell korrektere Codierung.

Was passiert, wenn ich versuche, Text zu decodieren, der eigentlich nicht codiert ist?

Klartext ohne %-Sequenzen wird unverändert zu sich selbst decodiert, da es nichts zu konvertieren gibt - die Decodierung schlägt nur fehl, wenn der Text eine unvollständige oder ungültige %-Sequenz enthält (wie ein % ohne zwei gültige folgende Hex-Ziffern).

Ist das dasselbe wie encodeURIComponent() in JavaScript?

Ja - die Codierung verwendet genau diese Funktion, die die Standardmethode ist, um einen einzelnen Wert (wie einen Query-Parameter) sicher für die Verwendung in einer URL zu codieren, im Gegensatz zu encodeURI(), das für die Codierung einer ganzen URL gedacht ist und Zeichen wie / und : unberührt lässt.
