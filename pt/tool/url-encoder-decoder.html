Perguntas frequentes

O que a codificação de URL faz?

Converte caracteres que não são seguros em uma URL (espaços, &, ?, #, e outros) em um sinal de porcentagem seguido de seu código hexadecimal - por exemplo, um espaço se torna %20 - para que o texto possa ser incluído com segurança em uma URL, como uma consulta de pesquisa ou valor de parâmetro.

Por que um espaço se torna %20 em vez de um sinal de mais (+)?

Ambos são usados na prática: %20 é a codificação padrão de porcentagem para um espaço em qualquer lugar de uma URL, enquanto + significa especificamente "espaço" apenas dentro de strings de consulta de URL (dados codificados de formulário), uma convenção legada de formulários HTML. Esta ferramenta usa %20, a codificação mais universalmente correta.

O que acontece se eu tentar decodificar texto que não está realmente codificado?

Texto simples sem sequências % é decodificado de volta a si mesmo sem alterações, já que não há nada para converter - a decodificação só falha se o texto contiver uma sequência % incompleta ou inválida (como um % não seguido de dois dígitos hexadecimais válidos).

Isso é o mesmo que encodeURIComponent() em JavaScript?

Sim - a codificação usa exatamente essa função, que é a forma padrão de codificar com segurança um único valor (como um parâmetro de consulta) para uso em uma URL, ao contrário de encodeURI() que é destinada a codificar uma URL inteira e deixa caracteres como / e : intocados.
